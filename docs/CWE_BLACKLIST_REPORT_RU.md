# Отчёт: чёрный список CW Expedition, /bl, /delstory

## 1. Изменённые и новые файлы
Новые:
- `cw/CweBlacklist.java` — единый постоянный список (`config/.../cwe-blacklist.json`, атомарная запись), очистка данных, журнал.
- `cw/CweCommands.java` — `/bl`, `/delstory`.
- `util/CweNotice.java` — полезная нагрузка отказа (отдельный маркер `CWE1`), строгий декодер.
- `mixin/PlayerManagerCweMixin.java` — изолированная проверка при входе (priority 2000, срабатывает только если обычная проверка банов пропустила игрока).
- `client/CweBlockedScreen.java` — экран «АККАУНТ НЕДОСТУПЕН».
- `test/.../CweNoticeTest.java` — 6 тестов.

Изменены (минимально): `AdminControlMod.java` (регистрация команд, тик), `AdminControlClient.java` (хук `ScreenEvents.AFTER_INIT`), `admin_control.mixins.json`, `HelpLists.java` (записи /bl и /delstory только для GA+), `CwStoryWorldService.java` (`backupJson`), `CwExpansionCommands.java` (подсказка в старой `/cw story reset`).

НЕ изменялись (проверено по датам файлов): `PunishmentNotice`, `PunishmentScreen`, `ModerationService`, `PlayerManagerMixin`, `MinecraftClientCursorMixin`, команды ban/jail/warn/kick.

## 3. Скриншоты
Приложены 4 изображения (2 уникальных экрана); использовались как визуальный референс компоновки. Фон — уже существующая в проекте картина Луи `textures/gui/luya_bg.png`; замок нарисован прямоугольниками. Новых иллюстраций не создавалось, фон не совпадает с референсом пиксель в пиксель.

## 4. GUI и fallback
Сервер при отказе входа отдаёт disconnect-текст, читаемый обычным клиентом (имя, статус, причина, дата, пояснение). Клиент с модом находит в hover-событии маркер `CWE1`, строго валидирует (тип, имя `[A-Za-z0-9_]{1,16}`, время 2000–2100) и показывает экран; весь остальной текст зашит в клиенте. Ник администратора не передаётся вообще.

## 5. Тесты
Мини-раннер (штатный `gradlew test` в этой среде не работает: нет `junit-platform-launcher` в офлайн-кэше и кириллица в пути): 33 из 33 прошли (6 новых + 27 прежних). Игровые сценарии вживую не проверялись.

## 6. Не сделано / не проверено
- Массовая ревизия и переименование команд (раздел 3 ТЗ): НЕ выполнена. Команд сотни, слепая замена запрещена ТЗ; требуется отдельная инвентаризация и согласование названий.
- Замена `true/false` на `enable/disable` — не выполнена.
- `perhelp` в проекте нет (есть `/phelp`, `/ahelp`); справка — ручной список `HelpLists`, не генерируется из диспетчера.
- Экран не проверен в клиенте; очистка аккаунта, вход зарезервированного имени, перезапуск, `/delstory` вживую не прогонялись.
- Очистка использует существующий `AccountReset` (прогресс, vanilla-файлы по точному UUID, сюжет) после резервной копии в `cwe-backups/`; записи наказаний он сохраняет.
