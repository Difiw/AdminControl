# CW Expedition — исправление сохранений, восстановления и строительного режима

JAR: `build/libs/admin-control-1.0.0.jar` (6 508 624 байт, SHA-256 `ee7e57edd6e0cd590c232ccc7e7b088a5ae3a81f01fa7314a5af5ddb059ec33c`).
Предыдущая версия сохранена: `build/libs-backup/admin-control-1.0.0.before-cw-persistence-fix.jar`.

## 1. Что было причиной

| Симптом | Причина (класс / метод) |
|---|---|
| `Failed to handle packet ... NullPointerException: Cannot invoke "ObjectSet.remove(Object)"` (оба скриншота) | Ванильный `ChunkTicketManager.handleChunkLeave`: `playersByChunkPos.get(...)` возвращает `null`, если участок, который «наблюдает» игрок, не зарегистрирован в этом мире (игрок оказался в мире без нормальной регистрации после прерванной смены измерения/профиля). Падает в `onPlayerMove` при пересечении границы секции (`class_2828$class_2830` = пакет движения). **Точный путь, как именно игрок рассинхронизировался, по скриншотам и без server `latest.log` установить нельзя**; исправлено само нарушение инварианта (см. ниже) и добавлена диагностика. `/buglist` — не причина: это баг-лист мода, он лишь показывает ошибку, залогированную ванильным `NetworkThreadUtils`. Его дедупликация не работала из-за хэша объекта (`@5993c52c`) в сигнатуре — исправлено. |
| Карта «пустая»/прогресс пропал | `CwStoryWorldService.enter` при КАЖДОМ входе копировал шаблон стройки поверх личного сюжетного мира (`CwTemplateSync.copy`) и затирал блоки, изменённые в сюжете. Теперь копирование — один раз на экземпляр (`Instance.seededAt`). |
| Файлы сюжета/стройки теряются или читаются пустыми | Запись без fsync, без резервной копии и контрольной суммы; повреждённый файл молча превращался в пустое состояние. |
| Утечки между профилями | Эндер-сундук NORMAL попадал в BUILD; эффекты не очищались; предмет на курсоре выпадал в мир; `RootVehicle` дублировал транспорт; `onDisconnect` записывал NORMAL-профиль как BUILD, если игрок не на стройке; пустой NORMAL-профиль мог быть выдан вместо отсутствующего; после падения в BUILD предметы BUILD терялись; админ с флагом полёта терял его после возврата. |
| После `/l` игрока тянуло в старые координаты | `AuthService` замораживал позицию на момент входа, а восстановление профиля телепортировало игрока уже после этого. Добавлен `AuthService.rebase`. |
| Сброс экземпляра удалял мир навсегда | `CwInstanceRegistry.processPending` теперь переносит папку в `dimensions/admin_control/_cw_trash/`. |

## 2. Что изменено

Новые классы (`ru.admincontrol.cw`): `CwDurable` (атомарная запись, fsync, SHA-256, `.bak`, карантин `*.corrupt-*`), `CwPlayerState` (машина состояний NORMAL→ENTERING_*→BUILD/STORY→EXITING→NORMAL + журнал `cw-journal/transitions.jsonl`, идемпотентность, защита от параллельных переходов), `CwProfile` (полная замена профиля без утечек), `CwSafeTeleport`, `CwDiagnostics`, `CwErrorLog`, `CwPersistenceSelfTest`; миксин `ChunkTicketManagerMixin`.
Переписаны: `CwBuilderWorld`, `CwStoryWorldService`. Изменены: `CwInstanceRegistry`, `CwTemplateSync`, `CwSaveStore`, `CwStoryService`, `CwStoryGraph`, `CwPointRegistry`, `CwBuilderEntry`, `CwMigrationService`, `CwCheckpointService`, `CwBuilderCommands`, `AdminControlMod`, `AuthService`, `ServerErrorWatch`, `NpcService` (метод `create` публичный для автотеста), `LumiraSelfTest`, `admin_control.mixins.json`.

Файлы на диске (папка данных мода, `<мир>/admin_control/`): `cw-player-state/<uuid>.json`, `cw-journal/transitions.jsonl`, `cw-diagnostics/server-errors.log` (полные стеки), `cw-reset-backups/`; остальные `cw-*.json` теперь в защищённом формате (старый читается и обновляется при следующей записи).

Админ-команды (корень `/cw`): `/cw diag [игрок]` (ГА) — пути, измерения, число загруженных чанков, фаза и хвост журнала; `/cw diag <игрок> restore confirm` и `/cw diag <игрок> resync confirm` (DEV) — безопасное восстановление / повторное копирование шаблона. Ничего не удаляется.

## 3. Изменения поведения (важно знать)

1. Повторный вход в сюжет **не** копирует шаблон заново. Чтобы игрок получил обновлённую карту: `/cw diag <игрок> resync confirm` (блоки его экземпляра заменятся); для админ-теста — «Начать заново».
2. Выход из игры во время сюжета больше не выбрасывает в основной мир: при следующем входе игрок возвращается в свой сюжетный мир с сохранённым профилем (окно смерти, как и раньше, возвращает в основной мир).
3. Выход из игры в BUILD: при входе восстанавливается NORMAL, BUILD-профиль сохраняется отдельно (вариант «контролируемый возврат»).
4. BUILD-профиль и мир стройки сохраняются раз в минуту, при выходе, отключении и остановке сервера.

## 5. Не проверено / ограничения

* Реальный клиент, вход через NPC «Луи», окно выбора, прозрачные переходы — только на сервере с фиктивным соединением.
* Kill процесса посреди перехода: проверена только сохранность фазы и её обнаружение после «перезапуска» (юнит-тесты), не сам `kill -9`. Одна смена профиля выполняется внутри одного тика, поэтому окно между записью и результатом очень узкое.
* Два игрока одновременно: независимость состояний проверена юнит-тестом, на сервере — одним игроком.
* Events (`InventoryVault`) не менялся; регрессия Events отдельно не гонялась.
* Первопричина рассинхрона игрока (шаг 1) не подтверждена стеком: нужен `latest.log` сервера. Теперь при следующем случае в логе будет строка `[CW] chunk-watch desync repaired ... transition=<id>` с полным путём вызова, а в `cw-diagnostics/server-errors.log` — полные стеки любых ошибок.
* В автотесте шаг Lumira `templateCopy` в 4 из 6 прогонов под JDK 21 зависал на загрузке чанка (в том числе при отключённом новом миксине); в двух последних прогонах прошёл. Причина не установлена; на вашем JDK 17 стоит прогнать `tools/selftest.ps1`.
* Gradle на этой машине запускается только на JDK 21 из каталога `C:\cwproj` с `GRADLE_USER_HOME=C:\cwgradle` и ASCII-временной папкой (JDK 17 не может создать `Pipe`, кириллица в путях ломает воркеры).

## 6. Установка и резервное копирование

1. Остановить сервер. Скопировать весь мир целиком (минимум `<мир>/admin_control/` и `<мир>/dimensions/admin_control/`).
2. Заменить `admin-control-*.jar` в `mods/` на новый (тот же JAR нужен и на клиенте — протокол клиента не менялся).
3. Запустить. В логе искать `CW migration:` и `[CW] builder world ready`.
4. Откат: вернуть прежний JAR **и** копию папки `admin_control/` (старая версия не читает файлы в новом защищённом формате).
