# CW Expedition: результат этапа 1

Дата исследования: 17 октября 2026 года.

## Проверенное состояние проекта

- Проект является модом `admin_control` для Minecraft 1.20.1, Fabric Loader 0.16.14,
  Fabric API 0.92.2 и Java 17.
- `/dserver` не является внешним API: это уже существующая команда Admin Control,
  открывающая `ServerPanelFactory`. В текущей панели нет настроек CW Expedition.
- Ранги являются внутренней системой Admin Control. ГА имеет уровень
  `AdminRanks.GA` (70), разработчик — `AdminRanks.DEV` (80). Проверка ГА+ может
  использовать существующий `CommandUtil.isHeadAdminSource`/`requireHeadAdmin`.
- Готовой реализации CW Expedition, команд `/cwexp`, сюжетных глав, персональных
  сюжетных профилей или персональных постоянных измерений в исходниках нет.
- `AuthWorld` — статически зарегистрированное измерение авторизации. Оно не является
  механизмом динамических персональных миров.
- `EventMapEditor` сохраняет область блоков для временной карты мероприятия. Это не
  полноценный отдельный `ServerWorld`, не хранит произвольное состояние мира и не
  подходит как реализация персонального сюжетного измерения.
- В проекте нет зависимости или исходников отдельного мода DServer. Поэтому награду
  нужно добавлять как новый раздел существующего `/dserver`, а не обращаться к
  вымышленному внешнему API.
- Серверная часть уже поддерживает необязательный клиентский мод. Диалог Expedition
  должен иметь серверный fallback (например, кликабельный текст), даже если позже
  будет добавлен улучшенный клиентский экран.
- Путь и содержимое шаблона сюжетной карты отсутствуют. В код и конфигурацию путь не
  добавлялся.

## Изменение сохранения в этом этапе

Общий JSON-слой Admin Control раньше перезаписывал рабочий файл напрямую. Теперь
запись выполняется через соседний `.tmp`, существующая валидная версия сохраняется
как `.bak`, а временный файл атомарно заменяет рабочий там, где файловая система это
поддерживает. На файловых системах без `ATOMIC_MOVE` применяется обычная замена.

Это ещё не хранилище Expedition, но устраняет выявленный риск в фундаменте, который
можно переиспользовать при реализации отдельных данных кампании.

## Архитектурная граница

CW Expedition следует реализовать отдельным серверным модулем внутри проекта, а не
расширением текущих квестов дерева навыков. Минимальное разделение ответственности:

1. `ExpeditionCatalog` — определения глав, обязательных целей и состояний
   `DRAFT`, `ACTIVE`, `ARCHIVED`.
2. `ExpeditionPlayerStore` — данные по UUID и главе, профили main/campaign,
   контрольная точка, решения, улики, журнал наград и состояние перехода.
3. `ProfileSwitcher` — транзакция `PREPARING -> MAIN_SAVED -> CAMPAIGN_APPLIED -> ACTIVE`
   и обратная транзакция с восстановлением после рестарта.
4. `InstanceManager` — создание, загрузка, сохранение и выгрузка персональных миров.
   Реализацию нельзя выбирать до прототипа динамического `ServerWorld` на 1.20.1.
5. `ProgressService` — процент как отношение завершённых обязательных весов к сумме
   весов; секреты хранятся отдельным показателем.
6. `RewardService` — выдача после атомарной фиксации уникального ключа
   `player UUID + chapter ID + reward revision`.
7. `ExpeditionCommands` и вход через NPC — тонкий интерфейс поверх сервисов, без
   самостоятельного изменения профилей или миров.

## Правило публикации глав

В каждый момент может существовать не более одной `ACTIVE` главы. Активация новой
главы в одной транзакции архивирует прежнюю. Архивирование запрещает обычный вход и
продолжение, но не удаляет прогресс, профиль или экземпляр мира. Новая активная глава
доступна каждому UUID независимо от состояния предыдущих глав. Физическая очистка
архивных экземпляров должна быть отдельной административной процедурой с dry-run,
резервной копией и сроком хранения.

## Блокирующие вопросы до следующих этапов

- Нужен фактический набор серверных/клиентских модов для проверки mod ID, registry ID
  и player-specific данных.
- Нужны лимиты хостинга: RAM, диск, число игроков и допустимое время подготовки мира.
- Нужен отдельный технический прототип жизненного цикла динамических миров Fabric
  1.20.1. Статическая datapack-регистрация не удовлетворяет персональному экземпляру
  на каждого UUID.
- Позже нужен реальный путь к рабочему миру карты. До его предоставления шаблон и
  операции клонирования не реализуются.

## План следующего инкремента

Следующий безопасный инкремент — независимое хранилище кампании и транзакционная
модель профилей без телепортации: сериализация полного vanilla-профиля, тест
переключения туда/обратно и восстановление искусственно прерванной транзакции. Только
после этого следует подключать прототип персонального мира.

## Что пока не заявляется реализованным

- переключение основного и сюжетного профиля;
- персональные измерения и их выгрузка;
- NPC и диалог входа;
- главы, прогресс, контрольные точки и награды;
- настройки Expedition в `/dserver`;
- команды `/cwexp`;
- интеграция предметов из других модов;
- сюжетная карта.
