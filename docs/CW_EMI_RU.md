# CW EMI — встроенный просмотрщик предметов и рецептов (Admin Control)

JAR: `build/libs/admin-control-1.0.0.jar` (Fabric 1.20.1, Java 17).

## Как открыть
Панель CW EMI появляется сама рядом с инвентарём, сундуком, верстаком, печью и т.д., в Creative и в рунных станциях. Справа по умолчанию, слева — в настройках (шестерёнка в шапке панели).

* ЛКМ по предмету — рецепты; ПКМ — «Используется в»; СКМ или Shift+ЛКМ — избранное.
* Клавиши (меняются в «Управление → CW EMI»): `R` рецепты, `U` применения, `A` избранное, `O` показать/скрыть панель, `Backspace` назад в окне рецептов. Работают над предметом в панели и над предметом в слоте контейнера; не срабатывают, пока вводится текст.
* Поиск: слова, `@мод`, `#тег`. В Creative-вкладке «Поиск» используется ванильная строка поиска.
* Окно рецептов: «Крафты в:» — ряд иконок реальных станций; клик по станции показывает только её рецепты; ПКМ по станции или кнопка «Как создать станцию» — рецепт самой станции. Клик по ингредиенту — его рецепты, ПКМ — применения. Назад/вперёд: кнопки `<` `>`, колёсико мыши листает рецепты станции, кнопки мыши 4/5 — история переходов.

## Что скрывается и как
Источник истины — `/dserver` → «Настроить список зашифрованных предметов» (ItemEncryption, синхронизация `enc_sync`). Новых списков нет; `cwStoryEnabled` не используется.

| Настройка /dserver | В CW EMI |
|---|---|
| Иконка скрыта | Предмета нет в сетке, поиске, избранном, истории; запрос рецептов/применений по его ID отклоняется сервером; в чужих рецептах он вырезается |
| Иконка открыта, название/описание скрыты | Предмет в каталоге с настоящей иконкой, название и описание — маской ItemEncryption; в текстовый поиск (название, ID, `@мод`, `#тег`) не попадает |
| Блокировка рецептов | Рецепты предметов из любого списка не отдаются (как и в `LumiraRecipeSyncMixin`) |
| Запрет использования | Раздел «Используется в» для такого предмета закрыт (консервативное решение) |
| Закрыта иконка станции | Станция и её рецепты не передаются; клиент видит единый индикатор «?» с перечёркиванием, подсказка строго «Недоступно», клик ничего не открывает |

Изменение настроек разработчиком применяется без перезахода: клиент получает `enc_sync`, очищает каталог, поисковый индекс, историю, избранное и кэш рецептов, открытое окно закрывается, если его предмет закрыт. Изменения рецептов (`RecipeEdits`, монеты) шлют пакет `emi_invalidate`.

## Протокол (EmiServer, версия 1)
`emi_hello` (S2C: версия, nonce) → `emi_ack` (C2S: nonce, версия, список конфликтующих модов) → `emi_query` (C2S: id запроса, режим, ID предмета) → `emi_result` (S2C: только разрешённые игроку рецепты и флаг «есть недоступное»), `emi_invalidate`. Запросы ограничены (всплеск 10, затем 8 в секунду), без подтверждённого ack сервер не отвечает. Ответ на неизвестный и на скрытый ID одинаков. Клиент без поддержки сервера работает в локальном режиме по рецептам, которые сервер ему и так отдал.

Связь с `CwClientGate`: вход в сюжетные измерения требует подтверждённого CW EMI-рукопожатия без конфликтов (`EmiServer.cwProblem`). Настройки `ModSettings`: `cwEmiEnabled` (по умолчанию true), `cwEmiEnforce` (по умолчанию false: отключать игроков, не ответивших на рукопожатие за 10 секунд; включайте только если на сервере нет игроков без мода).

## Несовместимые просмотрщики
Обнаружение по mod id в Fabric Loader (имена файлов не смотрятся): `emi`, `roughlyenoughitems` (REI), `jei`. Список расширяется строками mod id в `config/admin_control/cw_emi_incompatible.txt`. В `fabric.mod.json` добавлен мягкий `conflicts` (предупреждение загрузчика, игра не блокируется).

* Одиночная игра/LAN: после входа в мир клиент делает обычное «Сохранить и выйти» и показывает экран с названиями модов и инструкцией.
* Сервер с CW EMI: клиент отправляет ack со списком конфликтов и отключается сам; сервер дополнительно отключает такого игрока.
* Ограничения: вход нельзя остановить до загрузки мира (мир открывается и сразу корректно сохраняется); неизвестные просмотрщики не обнаруживаются; модифицированный клиент может солгать в ack — криптографической защиты клиента нет; если внешний мод падает до запуска проверки, это вне нашего контроля.

## Станции и рецепты
Верстак (фигурные и бесформенные), печь, плавильня, коптильня, костёр, камнерез, кузнечный стол (преобразование), Рунный верстак (всегда сетка 4×4 с категорией), Рунная наковальня (процесс ремонта: предмет + материал + топливо, не крафт; показывается только в «Используется в»), монеты из `/dserver` (бесформенный рецепт появляется только если он задан). Сторонние моды: рецепты из серверного `RecipeManager` с читаемыми ингредиентами и результатом; станция берётся из `Recipe.createIcon()`, а если API отдаёт стандартный верстак для нестандартного типа — показывается «Другой тип: id» без выдуманной станции. Новые адаптеры: `EmiConvert.register(Adapter)`. Адаптеров для Point Blank нет: мод не установлен и его API не изучен. Кузнечные отделки (trim) и «особые» рецепты без ингредиентов не показываются.

## Файлы
Новые: `emi/` (`EmiRecipe`, `EmiConvert`, `EmiFilter`, `EmiAccess`, `EmiIncompat`, `EmiServer`), `emi/client/` (`CwEmiClient`, `CwEmiOverlay`, `CwEmiRecipeScreen`, `CwEmiSettingsScreen`, `CwEmiConflictScreen`, `CwEmiConfig`, `CwEmiTheme`), `mixin/SmithingTransformRecipeAccessor`.
Изменены: `ItemEncryption` (методы `…For(player)`), `AdminControlMod`, `AdminControlClient`, `LumiraHud` (вызов обновления после `enc_sync`), `CwClientGate`, `CoinRecipes`, `ModSettings`, `CwPersistenceSelfTest`, `LumiraSelfTest`, `admin_control.mixins.json`, `fabric.mod.json`, `ru_ru.json`, `en_us.json`.

## Проверки
Серверный selftest (`gradlew runLumiraTest`) содержит шаги `EMI …`: станции и сетка 4×4, закрытая иконка, неизвестный ID, вырезание закрытых вариантов тега, закрытая станция при открытой обычной ветке, ремонт наковальни, динамический рецепт монеты (нет → появился → закрыт иконкой), запрет использования, права каталога, ограничение частоты, список несовместимых модов.

**Не проверено в живом клиенте** (запустить клиент здесь нельзя): внешний вид, раскладка панели при малых окнах и GUI scale, ввод в поле поиска, Creative-вкладки, горячие клавиши, экран отказа входа и реальное обнаружение EMI/REI/JEI, обновление открытого окна при смене настроек. Ручной сценарий: см. отчёт в чате.
